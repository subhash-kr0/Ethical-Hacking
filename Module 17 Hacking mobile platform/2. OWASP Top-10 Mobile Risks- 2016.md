# OWASP Top 10 Mobile Risks (2016)

The OWASP (Open Web Application Security Project) Mobile Top 10 is a list that identifies the most critical security risks faced by mobile applications. The 2016 edition highlights the following risks:

---

## 1. **M1: Improper Platform Usage**
- Misuse of platform features like keychain, TouchID, permissions, or intents.
- Includes failure to follow security best practices for the platform's API.

### Example:
- Misusing Android intents to expose sensitive data to unauthorized apps.

---

## 2. **M2: Insecure Data Storage**
- Storing sensitive data in unprotected locations (e.g., local storage, SQLite databases).
- Risk of theft if the device is compromised or data is extracted by malicious apps.

### Example:
- Storing user credentials in plaintext on the device.

---

## 3. **M3: Insecure Communication**
- Failure to secure data transmission between the mobile app and servers.
- Susceptible to eavesdropping, MITM (Man-in-the-Middle) attacks, or data tampering.

### Example:
- Not enforcing HTTPS or using weak TLS configurations.

---

## 4. **M4: Insecure Authentication**
- Weak authentication mechanisms that allow unauthorized access.
- Includes poor password practices, improper session handling, or lack of multi-factor authentication.

### Example:
- Allowing short, guessable passwords without brute-force protection.

---

## 5. **M5: Insufficient Cryptography**
- Using weak or improper cryptographic implementations to secure sensitive data.
- Includes custom or outdated encryption algorithms.

### Example:
- Encrypting sensitive data with a weak algorithm like MD5 or DES.

---

## 6. **M6: Insecure Authorization**
- Lack of proper checks to ensure that users only access data or actions they are authorized for.
- Over-reliance on client-side authorization checks.

### Example:
- An attacker modifying API requests to access restricted data.

---

## 7. **M7: Client Code Quality**
- Presence of code-level vulnerabilities such as buffer overflows, memory leaks, or race conditions.
- May lead to app crashes, data corruption, or exploitation by attackers.

### Example:
- Failing to handle unexpected input in the mobile app code.

---

## 8. **M8: Code Tampering**
- Altering the app’s code or behavior for malicious purposes.
- Includes reverse engineering, repackaging, or injecting malicious code.

### Example:
- Distributing a tampered app that includes spyware.

---

## 9. **M9: Reverse Engineering**
- Analyzing the app to extract sensitive information like source code, API keys, or backend logic.
- Typically done using tools like APKTool or IDA Pro.

### Example:
- Extracting hardcoded credentials from the decompiled app.

---

## 10. **M10: Extraneous Functionality**
- Unintended or hidden features that expose sensitive data or backend systems.
- Often includes leftover development or testing functionality.

### Example:
- Debugging endpoints left active in a production app.

---

## Mitigation Strategies
- Follow secure coding and testing practices.
- Use platform-recommended security APIs.
- Regularly update libraries and frameworks.
- Implement strong encryption and authentication mechanisms.
- Conduct regular penetration testing and code reviews.

---

By addressing these risks, organizations can significantly improve the security of their mobile applications and protect users from potential attacks.
