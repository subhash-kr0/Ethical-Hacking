# Introduction to CORS (Cross-Origin Resource Sharing)

CORS (Cross-Origin Resource Sharing) is a security feature implemented in web browsers to control how resources on a web server can be requested from a different domain. When a web page from one origin tries to make a request (like an HTTP request) to a different origin, the browser checks for CORS permissions. If the server allows the cross-origin request, the browser proceeds; otherwise, the request is blocked for security reasons.

## Key Concepts of CORS

- **Origin**: The origin of a web page is defined by the combination of the protocol (e.g., HTTP), domain (e.g., example.com), and port number (e.g., 80 or 443). For example, `https://example.com` and `http://example.com` are considered different origins due to the different protocols.

- **Preflight Request**: For certain types of requests (such as those with custom headers or methods like `PUT` or `DELETE`), the browser sends an HTTP request before the actual request, called the *preflight* request. This checks with the server if the requested action is permitted from the origin.

- **Access-Control-Allow-Origin**: This is the header used by servers to indicate which origins are allowed to access the resource. It can either allow all origins using `*` or specify specific origins.

## How CORS Works

1. **Request from a Different Origin**: When a web application tries to access a resource on a different origin, the browser sends an HTTP request to the server.

2. **Server Response with CORS Headers**: If the server supports CORS, it sends a response with the appropriate CORS headers that specify which origins are allowed to access the resource.

3. **Browser Validation**: The browser checks the response's CORS headers. If the origin is allowed, the browser processes the response. Otherwise, the browser blocks the request and logs a CORS error in the console.

## Common CORS Headers

- `Access-Control-Allow-Origin`: Specifies which origins are allowed to access the resource.
- `Access-Control-Allow-Methods`: Lists the HTTP methods (GET, POST, PUT, DELETE, etc.) allowed when accessing the resource.
- `Access-Control-Allow-Headers`: Specifies which headers can be included in the actual request.
- `Access-Control-Allow-Credentials`: Indicates whether credentials (cookies, HTTP authentication) can be sent with the request.

## Conclusion

CORS is essential for securing cross-origin requests and preventing malicious sites from interacting with resources that they shouldn't have access to. Understanding and properly configuring CORS is crucial for developing secure and functional web applications that interact with resources across different origins.
