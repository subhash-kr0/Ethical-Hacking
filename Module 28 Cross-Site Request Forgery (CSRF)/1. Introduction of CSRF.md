# Introduction to CSRF (Cross-Site Request Forgery)

## What is CSRF?

Cross-Site Request Forgery (CSRF) is a type of security vulnerability that occurs when a malicious actor tricks a user into performing unintended actions on a web application where they are authenticated. It exploits the trust a web application has in a user's browser by sending unauthorized commands from the user's account.

---

## Key Characteristics

1. **Exploits User Authentication:**
   CSRF attacks target authenticated users of a web application. If the user is logged in, their session information (like cookies) is used to authenticate malicious requests.

2. **Requires User Interaction:**
   The attacker usually needs to lure the user into clicking on a link, loading a malicious image, or visiting a specially crafted webpage.

3. **Stealthy in Nature:**
   These attacks often go unnoticed by users because they rely on the user's browser automatically including session cookies with requests.

---

## How CSRF Works

### Step-by-Step Process:

1. **Victim Authentication:**
   The victim logs into a legitimate website (e.g., a banking site) and maintains an active session.

2. **Malicious Setup:**
   The attacker crafts a malicious request designed to exploit the victim’s privileges.

3. **Execution:**
   The attacker tricks the victim into performing an action, such as clicking a link or loading a resource, which triggers the malicious request.

4. **Exploitation:**
   Since the victim's browser includes the authentication cookies automatically, the web application processes the request as if it originated from the victim.

---

## Examples of CSRF Attacks

1. **Bank Transfer Attack:**
   A malicious email or website contains a hidden form that triggers a money transfer from the victim's account to the attacker.

2. **Social Media Exploits:**
   An attacker posts a link that, when clicked, posts unauthorized updates or likes on the victim's social media account.

---

## Preventing CSRF

1. **CSRF Tokens:**
   Add unique, unpredictable tokens to requests that must be verified by the server.

2. **SameSite Cookies:**
   Use the `SameSite` attribute for cookies to restrict cross-origin requests.

3. **User Authentication Measures:**
   Require re-authentication for sensitive actions.

4. **Validate Referer Header:**
   Check the `Referer` or `Origin` headers to ensure requests originate from trusted sources.

5. **Implement CAPTCHAs:**
   Use CAPTCHAs to confirm user intent for critical actions.

---

## Conclusion

CSRF is a serious web security threat that can compromise user data and application integrity. By understanding its mechanics and implementing robust preventive measures, developers can significantly reduce the risk of such attacks.
