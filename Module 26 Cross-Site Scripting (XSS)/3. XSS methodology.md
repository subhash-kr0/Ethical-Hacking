# XSS Methodology

### 1. **Reconnaissance**
- Identify input points such as forms, URLs, headers, or any fields where user data is processed.
- Use tools like browser developer tools, proxies (e.g., Burp Suite), and crawlers to analyze the application.

### 2. **Payload Injection**
- Test with different payloads to determine if input is sanitized or filtered.
  Example Payloads:
  ```html
  <script>alert('XSS');</script>
  "'><script>alert("XSS")</script>
  <img src="x" onerror="alert('XSS')">
  ```

### 3. **Analyze the Response**
- Check the response to see if the payload is reflected back or stored.
- Use tools to inspect the DOM and script execution in the browser.

### 4. **Exploit Development**
- Once a vulnerability is identified, craft a more targeted payload:
  - Steal cookies using `document.cookie`.
  - Redirect victims to a malicious website using `window.location`.
  - Log keystrokes or manipulate the DOM.

### 5. **Persistence Testing**
- Test if the payload is stored persistently in the database.
- Check different user roles and access levels to verify the impact.

### 6. **Validation and Reporting**
- Document findings, including the affected endpoints, payloads used, and potential impacts.
- Provide remediation recommendations, such as input sanitization, output encoding, and implementing a Content Security Policy (CSP).

---

## Impacts of XSS
- **Data Theft:** Stealing session cookies, tokens, or sensitive information.
- **Account Hijacking:** Using stolen cookies or credentials to impersonate users.
- **Defacement:** Altering the appearance or functionality of a website.
- **Phishing Attacks:** Redirecting users to malicious sites.
- **Malware Delivery:** Injecting scripts that download and execute malicious software.

---

## Preventing XSS
1. **Input Validation and Sanitization:**
   - Validate all user inputs and sanitize output to remove malicious content.

2. **Encoding:**
   - Encode data before rendering it in the browser (e.g., HTML, JavaScript, URL encoding).

3. **Content Security Policy (CSP):**
   - Use a CSP header to restrict which scripts the browser is allowed to execute.
   ```
   Content-Security-Policy: script-src 'self';
   ```

4. **Use Secure Frameworks:**
   - Leverage secure frameworks like React or Angular, which escape user input by default.

5. **Avoid Inline JavaScript:**
   - Avoid using `onclick`, `onload`, or other inline event handlers.
