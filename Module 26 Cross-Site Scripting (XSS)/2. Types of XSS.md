# Types of XSS

### 1. **Stored XSS (Persistent XSS)**
- The malicious script is **permanently stored** on the target server (e.g., in a database, comment section, or user profile).
- The script executes whenever a victim retrieves and views the affected content.

#### Example:
- A comment field allows users to post comments without sanitizing input:
  ```html
  <script>alert('XSS Attack');</script>
  ```

### 2. **Reflected XSS (Non-Persistent XSS)**
- The malicious script is **reflected** off a web server and returned as part of the response.
- This type of attack typically involves tricking a victim into clicking a malicious link.

#### Example:
- A URL contains the payload:
  ```html
  http://example.com/search?q=<script>alert('XSS Attack');</script>
  ```

### 3. **DOM-Based XSS**
- The malicious script executes on the client-side, manipulating the DOM (Document Object Model) directly without server interaction.
- Vulnerabilities arise in JavaScript code running in the browser.

#### Example:
- JavaScript takes user input without proper validation:
  ```javascript
  document.write("<p>" + location.hash + "</p>");
  ```

---

## Impacts of XSS
- **Data Theft:** Stealing session cookies, tokens, or sensitive information.
- **Account Hijacking:** Using stolen cookies or credentials to impersonate users.
- **Defacement:** Altering the appearance or functionality of a website.
- **Phishing Attacks:** Redirecting users to malicious sites.
- **Malware Delivery:** Injecting scripts that download and execute malicious software.

---

## Preventing XSS
1. **Input Validation and Sanitization:**
   - Validate all user inputs and sanitize output to remove malicious content.

2. **Encoding:**
   - Encode data before rendering it in the browser (e.g., HTML, JavaScript, URL encoding).

3. **Content Security Policy (CSP):**
   - Use a CSP header to restrict which scripts the browser is allowed to execute.
   ```
   Content-Security-Policy: script-src 'self';
   ```

4. **Use Secure Frameworks:**
   - Leverage secure frameworks like React or Angular, which escape user input by default.

5. **Avoid Inline JavaScript:**
   - Avoid using `onclick`, `onload`, or other inline event handlers.
