# Testing Host Header Injection

Testing for Host Header Injection involves manipulating the `Host` header in HTTP requests to identify potential vulnerabilities. Here are the key steps:

1. **Modify the Host Header**:
   Use tools like `curl`, `Burp Suite`, or custom scripts to send HTTP requests with altered `Host` header values. For example:
   ```http
   GET / HTTP/1.1
   Host: malicious.example.com
   ```

2. **Observe the Application's Response**:
   Check for unusual behavior, such as:
   - Redirects to the malicious host
   - Inclusion of the malicious host in generated links
   - Unexpected error messages

3. **Test for Cache Poisoning**:
   - Alter the `Host` header and check if the response is cached.
   - Retrieve the cached resource using a legitimate `Host` header to see if the manipulated response is served.

4. **Validate SSRF Vulnerability**:
   - Test if altering the `Host` header causes the server to make unintended internal requests.

5. **Check Logs and Analytics**:
   - Inspect logs to identify if altered `Host` headers are improperly logged or used in analytics.

### Tools for Testing

- **Burp Suite**: For intercepting and modifying HTTP requests.
- **OWASP ZAP**: For automated security testing.
- **Custom Scripts**: Write Python or JavaScript scripts to test for injection manually.

### Mitigation Verification

After applying security measures, retest the application to ensure:
- The `Host` header is validated correctly.
- No unintended behavior occurs with altered `Host` headers.

Regular testing and monitoring are crucial to maintaining application security.
